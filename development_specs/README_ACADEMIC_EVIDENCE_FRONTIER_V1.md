## Intervention

The live code promotion controller now runs
`development_acceptance_frontier_v1.assess` if and only if:

1. It is a *native*, original authorized Windows source owner.
2. It has already attested current exact protected `main`.
3. The finite code task selector reports
   `SOURCE_G2G3_REQUIREMENT_TEST_JOBS_EXHAUSTED`.

The frontier verifies the latest original independent acceptance receipt
and reconciles *all eight* named source/science/acoustic/video/release gates
without confusing the single technical video-page match with an accepted
academic gate. It persists an atomic `academic_progress_watch_v1.json`
cursor; two consecutive unchanged cycles set `stall_escalation=true`.
Accepted G2 or academic gate counts can only increase; regression fails
closed for independent audit. The cursor never increments a success count
based on repeated polling, GitHub commits, or metadata parity.

If a previously saved Selenium source reply is quarantined, the frontier
checks **original saved bytes, original reply SHA, one original Send claim,
job SHA and byte-identical independent test SHA**. It stages one immutable,
no-Send *engineering repair assignment* in
`academic_recovery_work_items_v1`. This is not a new Gemini generation
request and is not allowed to relax the static source validator.
