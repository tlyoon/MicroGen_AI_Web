# Actual-voice provenance for restored TTS fallbacks — 17 October 2026

## Scope

This review-only correction follows PR #120, which restored standing routine Gemini Flash-Lite/Kore speech, Gemini Flash/Kore on retry exhaustion, and conditional Google Cloud Chirp3-HD/Corey only after both Gemini model queues fail. No real billable speech is generated by this correction.

### One authoritative effective identity

`selenium_pipeline.tts_effective_identity.verify_effective_identity()` validates the complete script-to-slide narration and exact provider/model/voice identity for each output WAV:

- Direct production: Flash-Lite/Kore or Flash/Kore, no fallback chain, `fallback_used=false` for every slide.
- Flash/Kore fallback: original requested identity Flash-Lite/Kore; `fallback_chain=[gemini-3.8-flash-lite-tts]` and whole-batch single-voice fallback evidence on every slide.
- Cloud Chirp3-HD/Corey fallback: original requested identity Flash-Lite/Kore; `fallback_chain=[gemini-3.8-flash-lite-tts, gemini-3.8-flash-tts]`, and actual Cloud/Corey for **all** slides, no Kore/Corey mixing. Missing or reordered fallback provenance fails closed.

These records are metadata evidence, not an independent acoustic voice check or a cryptographic record of API retry counts. Do not claim they prove that an actual provider outage occurred unless supported by preserved execution logs.

### Repair-review audit

`tts_qa_promotion.audit` no longer hardcodes Flash-Lite/Kore for every receipt. It verifies the actual effective provider/model/voice against the original source-linked TTS manifest, all slide narratives and the SHA-256 bound original, repair-attempt and proposed WAV files. The earlier PCM and >=99% fidelity gates still apply.

A human-listening attestation still must be separately supplied, externally stored and bound to the hashes. For Gemini Kore it requires `voice_kore_listening_verified=true`. For Cloud/Corey, it requires **`voice_corey_listening_verified=true`**; a Kore-only declaration is rejected. If a fallback changed the provider or model, it also requires **`fallback_provider_change_reviewed=true`**. These declarations are not digital signatures; only the actual human reviewer should issue them. No code generates or implies a real reviewer approval.

### Video handoff

`tts_reviewed_element_compat` checks the **actual** model and narrator in the reviewed handoff and authored scene `voice_id`. A Cloud/Corey handoff cannot be attached to a stale Flash-Lite/Kore scene, even when the WAV hashes match. Existing per-slide/per-element boundaries remain strict: one slide WAV cannot be silently treated as separate element-level recordings. Every MP4 part must be **strictly shorter than 600 seconds**, and the correct figure/text/equation highlight must match the actual spoken audio. Science, multi-panel figure quality, audio listening and decoded-pixel video QA remain release gates.

No original WAV or MP4 overwrite, no destructive sync of Drive-synced repos, no Zenbook, no Whisper/ASR, no automatic Moodle publication. Full production use remains blocked pending authentic speech, independent QA and separate publication authorization. HP/Dell-115/Yoga6 perform only offline tests in isolated temporary git checkouts.
