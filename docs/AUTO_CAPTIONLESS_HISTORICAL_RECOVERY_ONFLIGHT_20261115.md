# Automatic captionless historical-trial recovery — 15 November 2026

## Recovery guarantee and scope

This isolated Dell-115 development increment builds on commit `9583e76` (cross-page filename correction), itself based on the PR529 G2 branch `53dce13`. The normal `LectureAdvance` operator automatically attempts zero-Send recovery in two cases: (a) it encounters an immutable, previously failed terminal figure-stage receipt; or (b) a newly executed figure stage returns a terminal failure. Only an exact source-only, single-graphic `MAPPING_REVIEW_REQUIRED` refusal with independently verified original SHA/crop/geometry/log/model-ownership may be recovered. Unknown or ambiguous provider replies, numbered figures, multiple crops, cropped prose, altered evidence, and incomplete/unattributable attempts remain blocked.

Recovery uses a deterministic sibling under Windows `LOCALAPPDATA` with an immutable owned intent, a Windows kernel cross-process lock, and the unchanged historical failed-trial receipt. On restart, already-validated recovery is reused; an interrupted local copy can be rebuilt only inside that specifically owned and Send-free successor, never in the original trial. Any new-stage Send intent, changed contract, changed original PDF, or unknown intermediate state prevents cleanup and stops safely. The new result is explicitly *source-only structural recovery*, not provider success or scientific approval.

For an already-failed historical trial, normal `LectureAdvance` can recover the source-only figure and, when ordinary provider route/health gates permit, dispatch exactly one next stage (slides). For a failure occurring in the same invocation, it schedules/completes source-only recovery immediately, but preserves the existing one-model-stage-per-invocation cap; a subsequent ordinary pipeline invocation uses the persistent recovered successor. No background daemon or Windows scheduled task was created. The regular runner must be invoked again for the next model-bearing stage; a genuinely offline external provider cannot be recovered by local code.

## Release and future regression boundary

The scoped recovery scheduling, source-only historical salvage, restart and admission chain is implemented and verified on genuine historical source evidence. This is not a claim that a new live Gemini slide generation or any source-grounded visual/scientific QA, TTS, synchronized video or G2 release has passed. Hosted CI, branch integration, and a genuine permitted next-stage Send are separate acceptance gates; do not claim their results until observed. Never allow repeated failed original Gemini Sends just because a recovery successor exists.
