# Read-only re-audit of existing MicroGen highlighted lecture review videos

**17 October 2026 — draft, development-only.** This does not change the approved Gemini Flash-Lite/Kore → Gemini Flash/Kore → conditional Cloud Chirp/Corey narration contract.

## Why

The existing full-element highlight workflow already checks decoded pixels as a final step of generating a new, isolated review bundle. Its `verify_rendered()` entrypoint previously required writing a fresh JSON review file, however, making it awkward to recheck an **already-rendered** lecture without creating another result. The old `production_video_contract.verify_series()` also inspects receipt-declared `encoded_transition_qa`, but a prior JSON receipt is **not a substitute** for freshly decoding and comparing the actual encoded pixels.

This PR adds **`read_only_video_review_audit.audit_existing()`** and a CLI that reopens the original MP4s, confirms full source/slide/scene/element WAV SHA-256 binding, recomputes audio alignment and duration, and independently decodes the active pixel region for **every narrated source-linked equation, text block or figure panel**. All parts must have audio within the existing 590-second prerender safety margin and actual encoded duration **strictly <600 seconds**, with allowed timing drift. Source PDFs and all WAV files remain immutable.

## Invocation (existing complete review bundle)

```powershell
python -m selenium_pipeline.read_only_video_review_audit `
  --source "PATH_TO_ORIGINAL_SOURCE.pdf" `
  --slides "PATH_TO_SOURCE_BOUND_SLIDES.pdf" `
  --authored "PATH_TO_AUTHORED_PER_ELEMENT_PLAN.json" `
  --audio "PATH_TO_FROZEN_PER_ELEMENT_PCM_WAV_FOLDER" `
  --review-root "PATH_TO_EXISTING_REVIEW_BUNDLE"
```

The existing review bundle must contain its original `staged/` (with `series_inputs.json`, prepared instrumented PDF and separate WAV chunks) and `rendered/` (with the original encoded review MP4, geometry, cue timeline, verified receipts and `scratch_frames/` references). It must already have been generated by MicroGen's source-bound review workflow; a flattened export of MP4s and JSON claims is **not sufficient** to rerun independent pixel QA. Missing source-linked inputs are reported as a blocker; no partial successful result is fabricated.

**Read-only:** Unlike the original review-producing path, the new `audit_existing` uses `verify_rendered(..., output=None)` so it never creates another audit document or edits existing bundle entries. Decoded intermediate frame samples are extracted into temporary operating-system scratch directories and disposed of automatically. The returned structured JSON on stdout is technical information only. A previous `highlight_technical_review.json` is not accepted in place of fresh encoded-frame verification.

## Technical test and approval limitation

Unit integration tests render a genuinely encoded **3-slide, 2-part** synthetic lecture with local FFmpeg, verify all encoded pixels on two separate independent audit calls, and compare file SHA-256 snapshots before/after to prove the review tree was not modified. Separate tests tamper with the saved highlight reference image and MP4 bytes and simulate an exactly-600-second duration: **all must fail closed**. A legacy static `slides.mp4` by itself never qualifies. Tests cannot substitute for authentic scientific narration, source interpretation or human listening.

The real Thomas Calculus 8.4 October 16 historical review records **17 slides and 48 narrated elements**, split into two MP4s (approximately 291 and 323 seconds), but the available Google Drive review-package root `MicroGen_AI_Web_Thomas84_GenericRunnerHighlight_ReviewOnly_20261016` contains only two flattened review MP4s, a README and a summary JSON. That export does **not** contain the full `staged/rendered` bundle, so this new independent re-audit must **not** mark that exported pair as freshly pixel-verified without locating the complete original evidence. Earlier event counts and timestamps remain historic reported evidence, not fresh verification. The lecture's incomplete actual spoken-word QA also remains a release blocker.

All results must retain `scientific_semantic_mapping_approved=false`, `human_listening_approved=false`, `production_approved=false`, `student_published=false` until independently reviewed. This tool does not generate authentic speech, repair multi-panel figures, alter original files, publish to Moodle or merge drafts. Use only HP, Dell-115 and Yoga6 isolated testing workspaces. **Do not deploy or replace historical videos solely on technical FFmpeg tests.**
