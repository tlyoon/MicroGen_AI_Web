## Initially integrated G2 registry

`selenium_pipeline/recovery_registry_v1.json` is a source-controlled, structured history of 11 reviewed recovery signatures (G2 action/status, owned-browser transport diagnostic, offline independent-source work, and exact rendered-math operator ranking). Each records a stable identifier, component failure classification, applicable scope and environment, existing exact mechanism name, handler, prerequisites, verification test, finite retry policy and validation date. `selenium_pipeline/recovery_registry.py` is an executable loader: rejects missing/linked/oversized/invalid/duplicated entries, unknown handlers, retired mechanisms and external-code injection. It never dynamically executes registry content or authorizes a new provider Send.

The normal `selenium_pipeline/g2_forward_recovery_engine.py` now consults this registry for its **G2 source-review recovery action and terminal/deferred status**. Known signatures must match the installed code-reviewed implementation exactly or the stage halts before dispatch, and an unknown review action is forbidden. Each new forward intent includes the registry SHA for provenance; existing historical source-journal intents remain readable and continue through exact original source and previous-stage SHA verification. The existing source/quote/geometry/one-Send and cost gates remain authoritative.

This is intentionally **initial G2 integration**; it does not falsely claim that every other MicroGen module now uses one central registry. Extend the same mechanism only where verified live recovery handlers and realistic regression cases exist.
