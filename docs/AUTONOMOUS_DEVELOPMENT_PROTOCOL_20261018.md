# MicroGen_AI_Web — Standing Autonomous Development Protocol

**Effective: 2026-10-18. Owner-authorized contract amendment.**
**Authority:** Applies to subsequent active MicroGen_AI_Web development work, subordinate to the latest explicit owner contract. It supersedes earlier conversational habits of stopping after every recommended technical step.

## Default: continue, rather than asking “Proceed”

After an objective is authorized, continue through logically dependent and contract-compliant engineering steps without stopping after each implementation or asking for routine positive consent. Independently choose the next highest-impact development task, audit current code and source evidence, create an isolated feature branch, implement, run adversarial and regression tests, fix failures, update documentation and a durable checkpoint, and proceed to the next safe stage within the active development request.

Human academic/listening approval is **not** a prerequisite for internal generation or technical-stage progression. Automatic publication to the owner-verified YouTube channel (not Moodle) is within the owner's approved workflow after the independently mandatory technical safeguards, and only on the designated publisher PC. Do not fabricate human review; record technical-only status correctly.

### Binding invariants (not optional)

- Every generated lecture video part is **strictly <600 seconds**. Automatically split overlong topics into coherent parts. Narration highlights the *actual element being spoken about*, not merely a static slide, with decoded-pixel and audio timing verification.
- The actual textbook source, rendered figures and **all panels**, source page evidence, narration text, WAV/PCM, part assignments, hashes and reproducibility/QA receipts must pass current guards. Do not guess scientific meaning, panel identity or missing source links. Fail closed for unsupported cases, then develop a safe fix.
- TTS: approved routine Gemini **Flash-Lite/Kore** primary, three genuine transient-error attempts, **Flash/Kore** secondary after proper exhaustion, conditional **Cloud Chirp 3 HD/Corey** only after independently observed Lite + Flash exhaustion. One effective model and voice across the whole lecture. No Whisper, no ASR substitution or unrelated Cloud-storage lease. Credentials only in authorized local per-PC locations.
- Run on HP, Dell-115, Yoga6. Exclude Zenbook. Preserve Drive-native coordination, checksums and FIFO; no automatic reassignment if not authorized.
- Preserve all original PDFs, slide decks, captions, scripts, WAVs and existing MP4s, all three working-tree local modifications, archived branches, drafts and checkpointed content. No unreviewed destructive overwrite or surprise publication to Moodle.
- Keep one verified/pinned YouTube channel and one designated publisher; verify channel ownership, actual video privacy and playlist identity. No routine human academic approval, but no claim of actual publication before the API confirms it.
- Every feature PR remains isolated, **draft**, and based on the verified preceding dependency head unless prior explicit merge authorization or established repo policy allows otherwise. Do not silently merge stacked drafts or protected main.

### When to stop for owner discretion

Only when the next step genuinely needs a new owner policy decision, an external permission not yet covered by the contract, changed credentials/account/channel, destructive replacement, exceptional expenditure, a protected-main merge outside standing authorization, or conflicting requirements that cannot be resolved by strict safety-preserving engineering judgment. Continue with other independent safe tasks if possible.

### Operational limitation — no fictional background execution

An ordinary ChatGPT turn cannot run forever, survive an exhausted context as a self-resuming process, or open a new conversation by itself. Never promise future unscheduled work. On a context or tool boundary, write **CONTINUATION_CHECKPOINT_LATEST.md** containing the exact PR/branch/commit, original three-PC dirty-tree preservation, test/CI results, incomplete/unverified issues and the next executable task. A new conversation may resume from the checkpoint without repeating historical consent requests.

Persistent local/CI workers may run actual scheduled processes only when explicitly configured and verified; ChatGPT should accurately distinguish such processes from assistant activity.

### Development cycle

Audit -> contract and provenance check -> isolated implementation -> real synthetic/adversarial tests -> three-PC and GitHub CI verification -> draft PR and update checkpoint -> **next contract-safe task without a separate “Proceed” request**. Report meaningful milestones as information, not approval gates.
